## 3. 公共结构

`ResolutionRecordV1` 保持 S2 已冻结字段：

```ts
interface ResolutionRecordV1 {
  schemaVersion: '1';
  importer: string;
  specifier: string;
  mode: 'type' | 'web-dev' | 'web-build' | 'server' | 'test';
  target: 'shared' | 'web' | 'server';
  packageIdentity?: string;
  exportSubpath?: string;
  logicalPath?: string;
  format: 'esm' | 'json' | 'asset' | 'external';
  conditions: string[];
  external: boolean;
}
```

`schemaVersion` 是必要的机器版本字段；这是对 S2 阅读投影的补齐，不改变其解析语义。

## 4. 字段不变量

- `importer` 是仓库相对 POSIX 逻辑路径，不带 `./`，例如 `product/modules/notes/frontend/index.ts`。
- `logicalPath` 使用同一格式；不允许空 segment、`.`、`..`、反斜杠、URL、绝对路径、Windows drive、NUL、`.pnpm` 或 `node_modules` segment。
- `specifier` 保留源码原值；本批次不解析、不改写 extension。
- `packageIdentity` 与 `exportSubpath` 必须同时存在或同时缺失。
- `exportSubpath` 只能是 `.` 或以 `./` 开始且不含 traversal 的 subpath。
- 非 external 记录必须有 `logicalPath`，且 `format !== 'external'`。
- external 记录必须满足 `external: true`、`format: 'external'` 且没有 `logicalPath`。
- `packageIdentity` 表示 package export identity；Node built-in external 可以不提供它。
- 未知字段由 Schema 拒绝。

不要把真实路径先替换成逻辑路径。发现真实路径输入应失败，因为 normalizer 不知道正确 owner/package identity，静默删除前缀可能把逃逸路径伪装成合法路径。

## 5. Conditions 协议

输出 conditions 必须精确等于下表。调用方可以以任意顺序传入同一集合；normalizer 负责排序。缺失、额外或重复 condition 失败。

| mode | target | conditions |
| --- | --- | --- |
| `type` | 任意 | `types, import, default` |
| `web-dev` | `web` | `browser, development, import, default` |
| `web-build` | `web` | `browser, production, import, default` |
| `server` | `server` | `node, import, default` |
| `test` | `shared` | `test, import, default` |
| `test` | `web` | `browser, test, import, default` |
| `test` | `server` | `node, test, import, default` |

其他 mode/target 组合由 Schema 或 normalizer 拒绝。`type` 可以检查任意 target，但不代表它形成 runtime edge。

## 6. 函数和错误契约

```ts
normalizeResolutionRecord(input: ResolutionRecordInput): ResolutionRecordV1
```

`ResolutionRecordInput` 与输出字段相同，但 conditions 是调用方顺序。函数不得读取 cwd、环境变量、时间、随机数或文件系统。

失败抛出 `ResolutionRecordError`，包含按 `code:path` 稳定排序的 diagnostics：

| code | 用途 |
| --- | --- |
| `E_RESOLUTION_MODE_TARGET` | mode 与 target 不允许组合 |
| `E_RESOLUTION_CONDITIONS` | condition 缺失、额外或重复 |
| `E_RESOLUTION_LOGICAL_PATH` | importer/logicalPath 含机器路径或逃逸 segment |
| `E_RESOLUTION_PACKAGE_SHAPE` | packageIdentity/exportSubpath 未成对或 subpath 非法 |
| `E_RESOLUTION_EXTERNAL_SHAPE` | external、format、logicalPath 组合冲突 |

Diagnostic `path` 使用不带根 `$` 的字段名，并按以下优先级唯一归属：

| 错误 | path |
| --- | --- |
| mode/target 组合非法 | `mode` |
| condition 缺失、额外、重复 | `conditions` |
| importer 非法 | `importer` |
| logicalPath 非法或非 external 缺失 | `logicalPath` |
| 只有 packageIdentity | `exportSubpath` |
| 只有 exportSubpath | `packageIdentity` |
| exportSubpath 值非法 | `exportSubpath` |
| `format: external` 但 external 为 false | `external` |
| external 为 true但 format 不是 external | `format` |
| external 为 true但携带 logicalPath | `logicalPath` |

一次输入可以产生多个 diagnostics，去重后按 `code:path` 排序。测试将完整冻结 `code` 和 `path`；英文 `message` 用于人类解释，在 V1 不作为兼容 identity，但不得为空或遗漏字段值上下文。

Schema 负责 wire structure；normalizer 仍需执行跨字段语义。Schema 应用 `if/then` 或 `oneOf` 表达 mode/target、精确 conditions 数组及 external shape，使非法 wire document 不依赖 compiler 才失败。不要将 Ajv 引入 compiler runtime，本批次不增加依赖。

当前尚未选定 Schema-to-Type/validator generator，因此本批次按 Schema 手写同构 TypeScript 类型，并由 schema fixture 对账；这是一项明确的临时实现，不代表允许长期维护两份漂移契约。生成器在 S1 最终 validator/tooling 决策中接管后，必须用生成结果替换手写边界并保留同一 corpus。

## 7. 必测用例

正例：

- web-dev package export；
- server Node built-in external；
- relative JSON import；
- test/shared；
- conditions 输入顺序不同但输出 bytes 相同。

负例：

- `/Users/...`、`C:\\...`、反斜杠、`../`、`.pnpm`、`node_modules`；
- conditions 缺失、额外和重复；
- web-dev + server target；
- packageIdentity 没有 exportSubpath，或反向缺失；
- external false + format external；
- external true 仍携带 logicalPath；
- 非 external 没有 logicalPath；
- Schema 未知字段。

断言完整 diagnostic code/path 顺序，不只断言抛错。
